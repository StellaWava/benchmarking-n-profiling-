## The measurement contract

To keep the project coherent, every component is expected to answer the same five questions:

1. What is the available parallelism / critical-path length?
2. What is the arithmetic intensity (FLOPs per byte)?
3. What achieved GFLOP/s was measured?
4. What achieved bandwidth was measured?
5. Where does the result sit on the roofline, and how does it scale?

This is the discipline that turns a collection of experiments into a narrative of continuity.

If 1 Thread Block = 1024 threads, then 1 SM can hold exactly 2 blocks (1024 × 2 = 2048).
If 1 Thread Block = 256 threads, then 1 SM can hold exactly 8 blocks (256 × 8 = 2048).

16 × 16 Block: Equals 256 threads. Excellent for resource occupancy.
32 × 32 Block: Equals 1024 threads. This hits the exact hardware block limit.

In a grid; 
- Matrix C(M * N) = Matrix A(M * K) + Matrix B(K * N)
This means matrix A rows (i) of M  * matrix B columns(j) of N
thread(i,j), each thread can handle a single element. 
hence threads to rows and threads to columns
int row = blockIdx.y * blockDim.y + threadIdx.y;
int col = blockIdx.x * blockDim.x + threadIdx.x;

final GEMM equation:\(\text{Final\ Value}=(\alpha \times \text{sum})+(\beta \times C[\text{row}][\text{col}])\)

Overlapping and "Streaming" the Execution
- Pipelined Transfer: Stream 1 copies a chunk of Matrix A and B to the GPU.
- Asynchronous Compute: While Stream 1 executes the kernel calculation on the GPU, Stream 2 simultaneously copies the next chunk of data over the PCIe bus.
- Latency Hiding: This completely hides the slow PCIe transfer time behind active GPU math.

Temporal Streaming: Also known as data movement across the PCIe buses 
- Chunk rows of A and columns of B and stream....optimize memory latency 
Spatial Tiling: data movement inside the SM hardware. 
- Reduces global memory latency and SM memory bandwidth 
- get elements of matrix A and B from global memory into a shared array
i.e. __shared__
- using _syncthreads(), to ensure the tiles are fully loaded. 
- Perform dot pdt for the shared memory elements | Tile K 
- Repeat until all tile are complete, iteratively _syncthreads() all into a complete Tile K 

Use both approaches....
row * K finds the start of the specific horizontal row this thread is responsible for.
t * TILE_DIM jumps to the start of the current tile we are processing.
threadIdx.x tells the thread exactly which element inside that tile to grab.
